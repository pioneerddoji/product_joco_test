# 07. 용어와 추가 과제

## 핵심 용어

### 정적 사이트

서버가 요청마다 HTML을 새로 만들지 않고 준비된 HTML, CSS, JavaScript 파일을 그대로 전달하는 사이트입니다. GitHub Pages와 잘 맞습니다.

### MVP

가장 중요한 가설을 확인할 수 있는 최소 기능 제품입니다. 이 프로젝트에서는 첫 번호 생성 페이지가 해당합니다.

### canonical URL

내용이 같거나 비슷한 여러 주소 중 검색 엔진이 대표로 이해하기를 원하는 URL입니다.

### sitemap

검색 엔진에 공개 페이지 목록을 알려 주는 XML 파일입니다.

### robots.txt

검색 로봇에 크롤링 규칙과 sitemap 위치를 알려 주는 텍스트 파일입니다. 보안 도구가 아니며, 비밀 페이지를 숨기는 용도로 사용하면 안 됩니다.

### JSON-LD

검색 엔진이 페이지의 성격을 이해하기 쉽도록 JSON 형태로 넣는 구조화된 데이터입니다.

### localStorage

브라우저가 사이트별로 문자열 값을 저장하는 공간입니다. 이 프로젝트에서는 테마 선택만 저장합니다.

### 제3자 서비스

사이트 운영자가 직접 만들지 않고 외부 업체가 제공하는 기능입니다. Formspree, Disqus, Google AdSense, Google tag, Microsoft Clarity가 해당합니다.

### 측정 ID와 비밀 키

웹페이지에 넣는 분석 측정 ID나 광고 게시자 ID는 보통 공개를 전제로 하지만, API 비밀 키·액세스 토큰·서비스 계정 키는 공개 저장소에 넣으면 안 됩니다. 이름만 보고 판단하지 말고 서비스 문서를 확인해야 합니다.

### 자동 검증

반복 가능한 조건을 코드로 확인하는 절차입니다. 검증 범위 밖의 품질까지 보장하지는 않습니다.

## 초급 추가 과제

1. 생성 버튼을 누른 횟수를 화면에 표시한다.
2. “전체 복사” 버튼을 추가한다.
3. 결과가 없을 때와 있을 때의 안내 문구를 다르게 한다.
4. 새 학습 페이지를 만들고 sitemap과 검증 목록에 추가한다.
5. 모든 이미지와 아이콘에 접근 가능한 이름이 있는지 점검한다.

## 중급 추가 과제

1. 1~45 배열을 Fisher–Yates 방식으로 섞어 번호를 생성한다.
2. `scripts/verify.mjs`가 모든 HTML 파일을 자동 탐색하게 만든다.
3. header와 footer 중복을 정적 사이트 생성 과정으로 없앤다.
4. Playwright 같은 실제 브라우저 테스트를 추가한다.
5. GitHub Actions에서 push와 pull request마다 검증을 실행한다.

## 고급 추가 과제

1. Web Crypto의 난수와 `Math.random()`의 목적 차이를 설명하고 데모한다.
2. 콘텐츠 보안 정책(CSP)을 적용할 때 외부 스크립트별 허용 목록을 설계한다.
3. 분석 동의 상태에 따라 태그 로딩을 제어하는 구조를 설계한다.
4. 두 GitHub Pages 주소를 하나의 대표 URL로 정리하는 이전 계획을 만든다.
5. 성능, 접근성, SEO, 모범 사례를 CI에서 함께 점검한다.

## 토론 문제

### 문제 1

페이지가 8개에서 50개로 늘어났습니다. 지금 구조를 유지할 때 가장 먼저 생길 문제는 무엇이며, 어떤 도구를 도입하겠습니까?

### 문제 2

자동 검증은 통과하지만 Formspree 문의가 오지 않습니다. 코드, 운영 대시보드, 네트워크, 사용자 입력의 네 영역으로 진단 순서를 작성하세요.

### 문제 3

프로젝트 Pages와 사용자 Pages 양쪽에 같은 사이트가 열립니다. 검색·분석·댓글 관점에서 생길 수 있는 문제와 정리 방안을 제안하세요.

### 문제 4

Clarity를 제거하기로 결정했습니다. 스크립트만 지우면 충분하지 않은 이유를 설명하고 함께 수정할 파일과 검증을 나열하세요.

## 모범 답안의 방향

- 문제 1: 공통 HTML 중복, 링크·메타 누락, 수작업 갱신 비용을 지적하고 정적 사이트 생성기 또는 템플릿을 제안합니다.
- 문제 2: 엔드포인트와 HTML → 브라우저 네트워크 요청 → Formspree 프로젝트 상태·인증 → 스팸·수신 설정 순으로 증거를 확인합니다.
- 문제 3: 대표 URL을 결정하고 canonical, sitemap, robots, 분석 속성, Disqus 식별, Pages 배포를 일관되게 정리합니다.
- 문제 4: 모든 HTML, 개인정보처리방침, `verify.mjs`, 운영 대시보드, 쿠키·데이터 보관 설정까지 함께 검토합니다.
