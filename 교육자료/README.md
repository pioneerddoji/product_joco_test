# 번호연구소 제작·운영 교육자료

이 폴더는 [`product_joco_test`](https://github.com/pioneerddoji/product_joco_test)의 실제 커밋과 현재 소스를 바탕으로 만든 개인 교육자료입니다. 단순한 결과물 소개가 아니라, **작은 기능을 공개 가능한 정적 웹사이트로 확장하는 과정**, 그 과정에서 생기는 판단과 시행착오, 그리고 제3자가 직접 재현할 수 있는 실습을 함께 다룹니다.

> 기록 기준일: 2026-08-02
>
> 근거 범위: 저장소의 11개 커밋, 현재 소스, `scripts/verify.mjs`, GitHub Pages 설정
>
> 주의: 대화 중의 의도나 작업 당시의 감정은 커밋만으로 확인할 수 없으므로, 문서에서는 **확인된 사실**과 **교육적 해석**을 구분했습니다.

## 이 자료로 배우는 것

- HTML 한 파일의 시제품을 여러 페이지의 콘텐츠 사이트로 발전시키는 방법
- 바닐라 JavaScript로 중복 없는 번호 생성과 테마 저장을 구현하는 방법
- Formspree, Disqus, AdSense, Google tag, Microsoft Clarity 같은 외부 서비스를 붙일 때 확인할 것
- 검색 노출과 신뢰성을 위해 메타데이터, 정책 문서, `robots.txt`, `sitemap.xml`을 설계하는 방법
- 정규식·가상 DOM 기반의 가벼운 자동 검증과 그 한계
- Git 커밋을 프로젝트 일지이자 교육 자료의 근거로 사용하는 방법

## 현재 프로젝트 한눈에 보기

```text
브라우저
  ├─ index.html ── app.js / styles.css
  ├─ 학습·안내 페이지 7개
  ├─ Formspree ── 문의 전달
  ├─ Disqus ───── 공개 댓글
  ├─ AdSense ──── 광고
  ├─ Google tag ─ 방문 분석
  └─ Clarity ──── 사용 흐름 분석
          │
          └─ GitHub Pages ─ 정적 파일 배포
```

현재 저장소는 빌드 프레임워크나 패키지 설치가 필요 없는 정적 사이트입니다. 핵심 검증은 아래 한 줄로 실행합니다.

```powershell
node .\scripts\verify.mjs
```

기준 시점의 결과는 다음과 같습니다.

```text
PASS: 8 pages, links, SEO, AdSense, Formspree, Disqus, generator and theme verified
```

이 성공 메시지는 “모든 운영 기능이 실제로 정상”이라는 뜻이 아닙니다. 저장소 안에서 확인 가능한 구조와 일부 JavaScript 동작이 조건을 만족한다는 뜻입니다. 외부 서비스 수신, 광고 승인, 분석 데이터 유입, 모바일 브라우저 표현은 별도의 수동 검증이 필요합니다.

## 교육할 때 지켜야 할 원칙

- 결과보다 변경 이유를 먼저 설명합니다.
- 외부 서비스 ID는 비밀번호와 다르지만, 공개 가능 여부를 서비스별로 확인합니다.
- 확률 도구는 예측 도구로 과장하지 않습니다.
- 자동 검증 통과와 실제 사용자 경험을 같은 것으로 보지 않습니다.
- 커밋에서 확인되지 않는 시행착오는 사실처럼 단정하지 않습니다.
