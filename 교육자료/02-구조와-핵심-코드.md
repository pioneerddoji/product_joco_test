## 2. 번호 생성 알고리즘

핵심 함수는 1부터 45까지의 정수 중 서로 다른 6개를 뽑고 오름차순으로 정렬합니다.

```javascript
function generateSet() {
    var numbers = [];
    while (numbers.length < 6) {
        var number = Math.floor(Math.random() * 45) + 1;
        if (!numbers.includes(number)) numbers.push(number);
    }
    return numbers.sort(function (a, b) { return a - b; });
}
```

코드를 문장으로 번역하면 다음과 같습니다.

1. 빈 배열을 만든다.
2. 배열에 숫자가 6개가 될 때까지 반복한다.
3. 1~45 범위의 난수를 만든다.
4. 이미 뽑은 숫자가 아니면 배열에 넣는다.
5. 마지막에 오름차순으로 정렬한다.

`Math.random()`은 일반적인 화면용 무작위 선택에는 쓸 수 있지만 암호학적 보안이나 공정성이 법적으로 요구되는 추첨에는 적합하지 않습니다. 또한 번호 생성기가 당첨 가능성을 높이지 않는다는 설명이 반드시 따라야 합니다.

## 3. 출력 UI 만들기

버튼 클릭 시 기존 결과를 비우고 5개 행을 만듭니다. 각 행에는 세트 번호와 6개의 공이 들어갑니다. `innerHTML`로 긴 문자열을 조립하지 않고 `createElement`, `textContent`, `appendChild`를 사용해 구조를 명확히 했습니다.

숫자 범위에 따라 클래스만 다르게 붙이고 실제 색은 CSS가 담당합니다.

```javascript
function getColor(number) {
    if (number <= 10) return "yellow";
    if (number <= 20) return "blue";
    if (number <= 30) return "red";
    if (number <= 40) return "gray";
    return "green";
}
```

이 분리는 “데이터 판단은 JavaScript, 시각 표현은 CSS”라는 기본 원칙을 보여 줍니다.

## 4. 테마 상태 저장

페이지가 열릴 때 저장된 `theme` 값을 먼저 보고, 값이 없으면 운영체제 선호 색상을 사용합니다.

```javascript
var t = localStorage.getItem("theme");
document.documentElement.dataset.theme =
    t || (matchMedia("(prefers-color-scheme: dark)").matches ? "dark" : "light");
```

버튼을 누르면 `data-theme`을 바꾸고 `localStorage`에 저장합니다. CSS는 `:root[data-theme="dark"]`에서 색상 변수만 교체합니다. 이 방식은 컴포넌트마다 다크 모드 스타일을 반복하는 것보다 관리하기 쉽습니다.

주의할 점은 초기 테마 스크립트가 `<head>`에 있고, 실제 버튼 이벤트 코드는 `app.js`에 있다는 점입니다. 초기 스크립트를 먼저 실행하면 밝은 화면이 잠깐 보였다가 어두워지는 깜빡임을 줄일 수 있습니다.

## 5. 정적 사이트에서 문의 받기

문의 폼은 `action`을 Formspree 엔드포인트로 설정하고 `method="post"`를 사용합니다. 이 방식은 자체 서버가 없어도 폼을 받을 수 있습니다.

함께 확인해야 할 항목은 다음과 같습니다.

- 필수 입력, 이메일 타입, 최소 길이
- 개인정보 전송 동의
- 봇을 줄이기 위한 honeypot 필드
- Formspree 대시보드의 수신 주소와 스팸 설정
- 개인정보처리방침의 수집 항목·목적·보관 안내

HTML 검증만 통과해도 실제 메일이 오는 것은 아닙니다. 배포 환경에서 테스트 문의를 보내고 수신 여부까지 확인해야 합니다.

## 6. 댓글과 외부 스크립트

Disqus는 페이지 URL과 식별자를 지정한 뒤 외부 스크립트를 동적으로 추가합니다. 댓글 시스템을 빠르게 만들 수 있지만 다음 책임이 생깁니다.

- 공개 댓글 운영 원칙
- 스팸·개인정보 노출·유해 콘텐츠 관리
- Disqus 계정 및 사이트 shortname 관리
- 쿠키와 제3자 데이터 처리 안내
- 스크립트 차단 시 대체 안내

AdSense, Google tag, Clarity도 같은 원리입니다. **외부 스크립트를 추가한 커밋에는 정책 문서와 자동 검증 변경이 함께 있어야 한다**는 규칙을 세우면 누락을 줄일 수 있습니다.

## 7. SEO 관련 파일의 역할

- `<title>`: 검색 결과와 브라우저 탭의 제목
- `<meta name="description">`: 페이지 요약 후보
- canonical: 대표 URL 선언
- JSON-LD: 페이지 성격을 구조화된 데이터로 설명
- `robots.txt`: 검색 로봇에 크롤링과 sitemap 위치 안내
- `sitemap.xml`: 공개하고 싶은 URL 목록

canonical과 sitemap은 “어디에 배포할 것인가”에 종속됩니다. 사용자 사이트인 `https://사용자명.github.io/`와 프로젝트 사이트인 `https://사용자명.github.io/저장소명/`을 혼동하면 검색 신호가 분산될 수 있습니다.

## 8. 자동 검증 스크립트

`scripts/verify.mjs`는 외부 패키지 없이 Node.js 기본 모듈만 사용합니다.

검사 범위:

- 8개 페이지의 고유 title과 canonical
- AdSense, Google tag, Clarity 코드의 개수
- 설명 길이와 시맨틱 랜드마크
- 중복 `id`, label 연결, 내부 링크 대상
- 인라인 JavaScript 문법과 JSON-LD 파싱
- 문의 엔드포인트, Disqus, `ads.txt`, sitemap, robots
- 가상 DOM에서 번호 5세트 생성
- 번호 범위·중복·정렬
- 테마 전환과 저장

검사하지 않는 범위:

- 실제 브라우저 레이아웃과 접근성 전체
- 외부 서비스가 계정에 데이터를 전달하는지
- GitHub Pages의 최신 배포 완료 여부
- 링크된 외부 페이지의 상태
- 모든 한국어 문장의 자연스러움과 법률 적합성
- `Math.random()`의 통계적 품질

자동 검증은 안전망이지 품질 보증서가 아닙니다.
